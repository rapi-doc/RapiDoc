While declarative attributes handle foundational colors and typography, modern web products often demand bespoke styling—such as frosted glass sidebars, multi-stop gradient buttons, custom focus rings, or branded card containers.

Because RapiDoc is implemented as a standard W3C Web Component, standard external CSS selectors cannot pierce the Shadow DOM boundary. To give you complete design freedom without sacrificing encapsulation, RapiDoc exposes **CSS Shadow Parts** (`::part()`) and **CSS Custom Properties** (Variables).

---

## 1. How `::part()` Piercing Works

In your parent application stylesheet or `<style>` block, target `<rapi-doc>` followed by `::part(part-name)`:

```css
/* Target the navigation sidebar panel inside RapiDoc */
rapi-doc::part(section-navbar) {
  background: linear-gradient(180deg, #090d16 0%, #030712 100%);
  border-right: 1px solid rgba(56, 189, 248, 0.15);
  box-shadow: 4px 0 24px rgba(0, 0, 0, 0.4);
}

/* Target the header wrapper inside the navigation bar */
rapi-doc::part(section-navbar-header) {
  border-bottom: 1px solid rgba(255, 255, 255, 0.08);
  padding: 16px;
}
```

<Aside type="tip" title="CSS Part Chaining & Pseudo-Classes">
  CSS Shadow Parts support standard CSS pseudo-classes such as `:hover`, `:focus`, and `:active`. For example,
  `rapi-doc::part(btn-fill):hover` styles the primary action button on hover.
</Aside>

## 3. CSS Custom Properties (Design Tokens)

In addition to Shadow Parts, RapiDoc exposes a comprehensive set of CSS variables on `:host`. You can override these variables on `<rapi-doc>` or any ancestor container in your stylesheet or inline styles:

```css
rapi-doc {
  /* Override surface tokens */
  --background: #0b1121;
  --foreground: #f8fafc;
  --card: #0f172a;
  --border: #1e293b;

  /* Override typography tokens */
  --font-sans: 'Inter', sans-serif;
  --font-mono: 'JetBrains Mono', monospace;

  /* Override radius token */
  --radius: 8px;
}
```

## 4. Production Styling Recipes

### Recipe 1: Frosted Glass Sidebar with Neon Accents

```css
/* Frosted glass backdrop blur on sidebar */
rapi-doc::part(section-navbar) {
  background: rgba(10, 15, 26, 0.85);
  backdrop-filter: blur(16px);
  -webkit-backdrop-filter: blur(16px);
  border-right: 1px solid rgba(255, 255, 255, 0.08);
}

/* Sidebar header area (wrapping logo & search) */
rapi-doc::part(section-navbar-header) {
  padding: 16px;
  border-bottom: 1px solid rgba(255, 255, 255, 0.06);
}

/* Real-time search filter input inside sidebar */
rapi-doc::part(textbox-nav-filter) {
  background: rgba(15, 23, 42, 0.6);
  border: 1px solid rgba(56, 189, 248, 0.2);
  border-radius: var(--radius);
  color: #f8fafc;
  padding: 8px 12px;
}

rapi-doc::part(textbox-nav-filter):focus {
  border-color: #06b6d4;
  box-shadow: 0 0 0 3px rgba(6, 182, 212, 0.2);
}
```

### Recipe 2: Gradient Action Buttons & "TRY" Triggers

```css
/* Base button enhancements */
rapi-doc::part(btn) {
  border-radius: var(--radius);
  font-weight: 600;
  transition: all 0.2s cubic-bezier(0.16, 1, 0.3, 1);
}

/* Primary filled buttons (TRY execution, copy, search) */
rapi-doc::part(btn-fill) {
  background: linear-gradient(135deg, #06b6d4 0%, #3b82f6 100%);
  color: #ffffff;
  border: none;
  padding: 8px 16px;
  box-shadow: 0 4px 12px rgba(6, 182, 212, 0.25);
}

rapi-doc::part(btn-fill):hover {
  transform: translateY(-1px);
  box-shadow: 0 6px 16px rgba(6, 182, 212, 0.4);
}
```

### Recipe 3: Custom Server Environment Panel

```css
/* Server selector container */
rapi-doc::part(section-servers) {
  background: rgba(15, 23, 42, 0.7);
  border: 1px solid rgba(56, 189, 248, 0.2);
  border-radius: var(--radius);
  padding: 16px 20px;
}

/* Selected base URL indicator */
rapi-doc::part(label-selected-server) {
  color: #38bdf8;
  font-family: var(--font-mono);
  font-weight: 600;
}
```

<Aside type="tip" title="Recommended Architecture">
  The recommended workflow is setting foundational colors and typography using declarative HTML attributes (`theme`, `color-scheme`,
  `radius`, `scale`), and reserving `::part()` for high-impact visual customizations such as gradients, backdrop filters, and custom
  container borders.
</Aside>

## 5. Schema Descriptions: Truncation & Expanding

In both **Tree mode** and **Table mode**, each schema row shows its description on a single line. Click a description (or its `➔` arrow) to expand that row, and click again to collapse it. The **Multiline description** toolbar button expands every row at once.

### Layout Differences

<Tabs>
  <TabItem label="Tree Mode Structure">
    In **Tree mode**, property names, data types, constraints, and descriptions are displayed in a continuous, hierarchically indented horizontal line:

    <div style="margin: 16px 0; border-radius: 8px; overflow: hidden; border: 1px solid rgba(255, 255, 255, 0.1);">
      <img src="/assets/images/schema-tree-mode.png" alt="RapiDoc Schema Tree Mode Structure" style="width: 100%; display: block;" />
    </div>

    - **Field Column**: Has a dynamic minimum column width (`min-width: calc(400px - indent)`).
    - **Long Property Names**: Truncated with an ellipsis, with the full name in a hover tooltip (`title="..."`). Expanding the row also shows the full name.
  </TabItem>
  <TabItem label="Table Mode Structure">
    In **Table mode**, the schema is formatted into a strict 3-column CSS subgrid:

    <div style="margin: 16px 0; border-radius: 8px; overflow: hidden; border: 1px solid rgba(255, 255, 255, 0.1);">
      <img src="/assets/images/schema-table-mode.png" alt="RapiDoc Schema Table Mode Structure" style="width: 100%; display: block;" />
    </div>

    - **Field Column (`.key`)**: Dedicated column with a width controlled by `--table-schema-key-width` (default: `240px`). Long property names truncate with an ellipsis and show full text via hover tooltips (`title="..."`).
    - **Type Column (`.key-type`)**: Fixed minimum column (~150px) displaying data types and nullability badges.
    - **Description Column (`.key-descr`)**: Flexible `1fr` column spanning the remaining container width.
  </TabItem>
</Tabs>

### What a collapsed row shows

| Description content | Collapsed row | `➔` arrow |
| :--- | :--- | :--- |
| One paragraph that fits | The whole paragraph | No |
| One paragraph that is too long for the column | The start of the paragraph, cut off with a cue (see below) | No |
| Several paragraphs, a list with several items, or a `<br>` line break | The first paragraph or list item | Yes |
| A description plus constraints, default, allowed values or pattern | The description; the constraint chips are hidden | Yes |
| Constraints only, no description | The constraint chips | No |
| Nothing | An empty cell | No |

Whether a line is too long is decided by the browser at the actual column width and font, not by counting characters, so it adapts to split panes, sidebars and resizing without any JavaScript.

### The truncation cue

- **Chrome and Edge (133+)**: a cut-off line ends with a small button-style `…` badge, shown only on rows that are actually cut off. Those rows also get a pointer cursor. This uses a CSS [scroll-state container query](https://developer.chrome.com/blog/css-scroll-state-queries).
- **Other browsers**: a cut-off line ends with a bold ellipsis in the primary color.

Both use `--primary` (and `--primary-foreground` for the badge on hover), so they follow your theme.

```css
rapi-doc {
  /* Allocate more width for property names in Table mode */
  --table-schema-key-width: 300px;
}
```

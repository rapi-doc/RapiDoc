In comprehensive API specifications with dozens or hundreds of operations, enabling developers to navigate effortlessly between related endpoints, authentication guidelines, data models, and external resources is essential.

RapiDoc provides an intelligent **deep navigation and linking architecture** that works natively with standard Markdown links, Web Component slots, URL routing, and sidebar table of contents.

## 1. Internal Deep Linking

RapiDoc assigns deterministic, predictable DOM element IDs to every primary section, tag group, and operation card in the documentation. You can reference these IDs in standard Markdown link syntax (`[Label](#element-id)`) anywhere within OpenAPI description strings.

When a user clicks an internal link, RapiDoc:

1. Updates the browser's URL hash (e.g. `https://api.example.com/docs#get-user`).
2. Automatically expands the target tag group and endpoint accordion if it was collapsed.
3. Smoothly scrolls the element into view across all render modes (`read`, `view`, and `focused`).

### ID Generation Rules

The table below outlines how RapiDoc constructs element IDs across your specification:

| Target Section            | Generated Element ID              | Formatting Rule & Logic                                                                                                                         |
| :------------------------ | :-------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------- |
| **Overview Section**      | `overview`                        | Static identifier for the API title, version, and general description card.                                                                     |
| **API Servers**           | `servers`                         | Static identifier for the server configuration and URL selector panel.                                                                          |
| **Authentication**        | `auth`                            | Static identifier for security schemes (Bearer tokens, API keys, OAuth).                                                                        |
| **Tag Group (Top-level)** | `tag-group--{group-name}`         | Prefix `tag-group--` followed by sanitized group name from `x-tagGroups`.                                                                       |
| **Tag Section**           | `tag--{tag-name}`                 | Prefix `tag--` followed by the sanitized tag name.                                                                                              |
| **Path / Operation**      | `{operation-slug}`                | Built from the `operationId`, else the `summary`, else the method and path (see below). With `x-tagGroups` the ID is `{tag}--{operation-slug}`. |
| **Overview Headings**     | `overview--{heading-slug}`        | Prefix `overview--` followed by GitHub-slugger formatted heading text.                                                                          |
| **Tag Headings**          | `tag--{tag-name}--{heading-slug}` | Tag element ID followed by GitHub-slugger formatted heading text.                                                                               |

### Operation IDs

An operation's ID comes from the first of these that is available:

1. **`operationId`** in kebab-case, when it is at most 45 characters and not a placeholder such as `operation1`: `getUserById` &rarr; `get-user-by-id`.
2. **`summary`** in kebab-case, cut at a word boundary after 40 characters: `Get a user by ID` &rarr; `get-a-user-by-id`.
3. **Method and path**: `GET /users/{userId}` &rarr; `get-users-userId`.

Duplicates get the method as a prefix (`post-webhooks`), then a number (`-1`). An ID built from the summary changes whenever the summary is edited, so give operations an `operationId` when links to them should last. `rapidoc validate` and the portal's `rapidoc dev` / `rapidoc build` list operations without one.

Every operation can also be reached by its **method + path anchor**, whatever its ID: `#get-users-userId` or, for `DELETE /orgs/{orgId}/teams/{teamId}/members/{userId}`, `#delete-orgs-orgId-teams-teamId-members-userId`. Case and punctuation are ignored, so links in the format of older RapiDoc versions (`#get-/users/-userId-`) keep working.

Tag and tag group IDs use the kebab-case name: tag group `Shipment Logistics` &rarr; `tag-group--shipment-logistics`, tag `User Management & Auth` &rarr; `tag--user-management-auth`.

## 2. 3-Tier Navigation Hierarchy (`x-tagGroups` / `x-tag-groups`)

For large enterprise APIs with dozens of domain categories, standard 2-tier navigation (Tag &rarr; Operation) can produce an overly long sidebar. RapiDoc natively supports the **`x-tagGroups`** (and kebab-case **`x-tag-groups`**) top-level vendor extension, popularized by ReDoc and developer portals like Zudoku / Cosmo Cargo.

When declared at the root of your specification, RapiDoc organizes tags into collapsible high-level groups across the sidebar, `view` mode accordions, and `read` mode section breaks:

```yaml
openapi: 3.1.0
info:
  title: Enterprise Logistics API
  version: 2.0.0

# 3-Tier Navigation grouping
x-tagGroups:
  - name: Shipment Management
    description: Core shipment dispatch, rates, and tracking endpoints
    tags:
      - Shipments
      - Tracking
      - Rates
  - name: Billing & Accounts
    description: Customer invoicing, payments, and account balances
    tags:
      - Invoices
      - Payments

tags:
  - name: Shipments
    description: Dispatch and label generation
  - name: Tracking
    description: Real-time milestone status
```

### Controlling Initial Expansion (`x-tag-expanded`)

You can control whether groups or tags start expanded or collapsed using `x-tag-expanded`:

```yaml
x-tagGroups:
  - name: Advanced Analytics
    x-tag-expanded: false # Collapsed by default
    tags:
      - Metrics
      - Telemetry
```

<Aside type="note" title="Unified Click & Interaction Behavior">
  All clicks on tags or tag-groups in the sidebar uniformly expand or collapse the section, and automatically highlight the parent container
  when child endpoints are selected. The previous attributes `on-nav-tag-click` and `nav-active-item-marker` have been deprecated in favor
  of this standardized interaction and left-bar active styling.
</Aside>

## 3. Writing Cross-References in OpenAPI Specs

You can embed Markdown links inside any OpenAPI text field, including `info.description`, tag descriptions, operation descriptions, parameter descriptions, and response explanations.

### Practical Example: Linking Endpoints Together

Here is a typical workflow where a `POST /users` endpoint references the companion `GET /users/{userId}` endpoint and the API authentication panel:

```yaml
openapi: 3.0.2
info:
  title: User Accounts API
  version: '1.0.0'
  description: |
    Welcome to the User Accounts API.

    - [Review Authentication Requirements](#auth)
    - [Configure API Servers & Environments](#servers)
    - [Browse User Operations](#tag--Users)

tags:
  - name: Users
    description: Operations for managing user profiles and security credentials.

paths:
  /users:
    post:
      tags:
        - Users
      summary: Create a new user profile
      description: |
        Creates a new user record in the database.

        After creation, retrieve the full profile details using 
        [GET /users/{userId}](#get-/users/-userId-).

        Before invoking this endpoint, ensure your client has obtained a valid 
        bearer token as described in the [Authentication Guide](#auth).
      responses:
        '201':
          description: User successfully created

  /users/{userId}:
    get:
      tags:
        - Users
      summary: Get user by ID
      description: |
        Retrieves a single user record by their unique identifier.
        To register a new user, use [POST /users](#post-/users).
      parameters:
        - name: userId
          in: path
          required: true
          schema:
            type: integer
      responses:
        '200':
          description: User record found
```

## 4. Sidebar Headings in the Navigation Bar

When authoring comprehensive documentation inside `info.description`, you may want major topic headings to appear directly inside the sidebar navigation bar alongside endpoints.

RapiDoc provides the `info-description-headings-in-navbar` attribute:

```html
<rapi-doc spec-url="/specs/links.yaml" render-style="read" info-description-headings-in-navbar="true"> </rapi-doc>
```

### How It Works

1. During specification parsing, RapiDoc inspects `info.description` for Markdown heading tokens (`#` for level-1 and `##` for level-2).
2. It parses the heading text and generates slugified anchor IDs prefixed with `overview--` (e.g. `## Rate Limiting & Quotas` &rarr; `overview--rate-limiting--quotas`).
3. These headings are inserted as nested navigation items under the **Overview** menu entry in the sidebar.
4. Clicking any heading smoothly scrolls the viewport to that exact section of the description.

<Aside type="note" title="Render Style Availability">
  Sidebar heading extraction is actively rendered in **Read** mode (`render-style="read"`), where a continuous sticky navigation sidebar is
  displayed.
</Aside>

<Aside type="tip" title="Dedicated Markdown Headings Guide">
  For complete examples, tag description headings, heading level rules, and CSS Shadow Parts customization, see our dedicated [Markdown
  Headings in Navbar Guide](/docs/advanced/markdown-headings/).
</Aside>

## 5. URL Routing & Deep Link Sharing

To enable seamless bookmarking, browser back/forward history navigation, and team link sharing, enable RapiDoc's route synchronization:

```html
<rapi-doc spec-url="/specs/petstore.json" update-route="true"> </rapi-doc>
```

### Configuration Attributes

| Attribute         | Type      | Default    | Description                                                                                                                                                  |
| :---------------- | :-------- | :--------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `update-route`    | `boolean` | `"true"`   | When `true`, automatically updates the browser URL hash as the user scrolls through or clicks operations. Set to `"false"` to disable URL hash modification. |
| `goto-path`       | `string`  | `""`       | Target element ID to automatically scroll/navigate to immediately after the specification loads if no URL hash is present.                                   |
| `scroll-behavior` | `string`  | `"smooth"` | Controls scrolling animation style (`"smooth"` or `"auto"`).                                                                                                 |

### SPA Framework Integration (Vue, React, Angular)

When embedding `<rapi-doc>` inside an SPA framework where the host router manages URL state, disable internal URL updates and listen to the `@nav-active-change` event:

```html
<rapi-doc spec-url="/specs/petstore.yaml" update-route="false" :goto-path="activeEndpoint" @nav-active-change="handleNavChange"> </rapi-doc>
```

## 6. Custom HTML Links via Web Component Slots

RapiDoc exposes slots that let you insert custom navigation components (e.g. breadcrumbs, cross-documentation links, developer portal banners) that link into specific API sections.

Unlike Markdown links, slotted HTML links allow complete control over typography, custom colors, icons, badges, and layout:

```html
<rapi-doc spec-url="/specs/links.yaml" show-header="true">
  <!-- 1. Header Slot: Top utility bar links -->
  <div slot="header" style="display: flex; align-items: center; gap: 16px;">
    <a href="#servers" style="color: #cbd5e1; text-decoration: none; font-size: 13px;"> 🌐 Servers </a>
    <a href="#auth" style="color: #cbd5e1; text-decoration: none; font-size: 13px;"> 🔒 Auth </a>
    <a
      href="https://github.com/rapi-doc/RapiDoc"
      target="_blank"
      style="color: #38bdf8; text-decoration: none; font-size: 13px; font-weight: 600;"
    >
      GitHub ↗
    </a>
  </div>

  <!-- 2. Default Slot: Quick-jump announcement banner above Overview -->
  <div
    style="background: rgba(56, 189, 248, 0.08); border: 1px solid rgba(56, 189, 248, 0.2); padding: 12px 16px; border-radius: 8px; margin: 16px;"
  >
    <span style="font-weight: 600; color: #f8fafc;">🚀 Quick Navigation:</span>
    <span style="margin: 0 8px; color: #64748b;">|</span>
    <a href="#get-/users/-userId-" style="color: #38bdf8;">User Profile Endpoint</a>
    <span style="margin: 0 8px; color: #64748b;">•</span>
    <a href="#post-/users" style="color: #38bdf8;">Create User Endpoint</a>

  <!-- 3. Nav-Logo Slot: Top of sticky sidebar -->
  <div slot="nav-logo" style="padding: 12px 16px; border-bottom: 1px solid rgba(255, 255, 255, 0.1);">
```

## 7. Programmatic JavaScript Navigation

You can also trigger navigation programmatically from your host application's JavaScript code using RapiDoc's public DOM methods:

```javascript
const rapidoc = document.querySelector('rapi-doc');

// Scroll and focus on a specific operation
await rapidoc.scrollTo('get-/users/-userId-');

// Or navigate to a tag group
await rapidoc.scrollTo('tag--Users');

// Or navigate to the servers section
await rapidoc.scrollTo('servers');
```

### Listening to Navigation Events

You can detect when the active route changes by listening to standard browser `hashchange` events:

```javascript
window.addEventListener('hashchange', () => {
  const currentHash = window.location.hash;
  console.log('Active RapiDoc section changed to:', currentHash);
});
```

## Summary Best Practices

1. **Verify Sanitized Character Rules**: Remember that `{` and `}` surrounding path parameters are replaced by hyphens. A path `/items/{id}` becomes `get-/items/-id-`.
2. **Cross-Link Complementary Operations**: Use Markdown links in operation descriptions to connect `POST` creation endpoints with corresponding `GET` retrieval and `DELETE` endpoints.
3. **Organize Large Descriptions with Headings**: For long architectural introductions, activate `info-description-headings-in-navbar="true"` to create a structured table of contents in the sidebar.
4. **Leverage Slots for Brand Utility**: Place external documentation, developer console links, and environment status indicators into the `header` slot for universal visibility.

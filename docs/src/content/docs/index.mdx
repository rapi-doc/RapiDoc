**RapiDoc** turns an OpenAPI spec into interactive API documentation. At its core is `<rapi-doc>`, a single HTML element with no runtime dependencies: add one script tag and it works in any page or framework. Its Shadow DOM keeps your site's styles and RapiDoc's styles apart.

## What you can build

<CardGrid>
  <Card title="API reference" icon="open-book">
    `<rapi-doc>` renders navigation, search, schemas, examples, authentication and a **Try** console. Choose one long page, expandable sections, or one operation at a time. [Quickstart](/docs/get-started/quickstart/)
  </Card>
  <Card title="Your look" icon="pencil">
    Five built-in themes, any brand color, light and dark, and full control through CSS custom properties and `::part()`. [Theming](/docs/theming/overview/)
  </Card>
  <Card title="Embedded endpoints and workflows" icon="puzzle">
    `<rapi-doc-mini>` puts a single endpoint in a blog post; `<rapi-flow>` draws Arazzo workflows and runs them. [RapiDoc Mini](/docs/rapidoc-mini/) · [RapiFlow](/docs/rapi-flow/)
  </Card>
  <Card title="Mocks" icon="random">
    Answer requests from the spec, in the page or as an HTTP server with request validation and token checks. [Mocking](/docs/mocking/overview/)
  </Card>
  <Card title="A PDF of the reference" icon="document">
    `<rapi-pdf>` makes a PDF of the spec in the browser; `rapipdf/node` and `rapidoc pdf` make the same one in a build. [RapiPdf](/docs/rapipdf/)
  </Card>
  <Card title="Checks in CI" icon="approve-check">
    Validate, lint and bundle the spec with the `rapidoc` command, with errors shown on the pull request. [RapiDoc CLI](/docs/cli/)
  </Card>
  <Card title="Tools for AI agents" icon="rocket">
    Turn the spec into a curated MCP server, from a button in `<rapi-doc>`, the command line or Node. [MCP Server](/docs/ai/mcp-server/)
  </Card>
  <Card title="Developer portals" icon="laptop">
    API references next to Markdown guides, with search and optional single sign-on (SSO), built with the `rapidoc` CLI. [Packages](/docs/get-started/packages/#developer-portals)
  </Card>
</CardGrid>

## How these docs are organized

The switcher at the top of the sidebar picks a product, and the sidebar below it shows that product's pages:

- **RapiDoc**: `<rapi-doc>` itself. Getting started, theming, customizing, authentication, the JavaScript API, performance, mocking, MCP, and the migration guides.
- **RapiDoc Mini** and **RapiFlow**: `<rapi-doc-mini>` and `<rapi-flow>`.
- **RapiPdf**: `<rapi-pdf>` and `rapipdf/node`, an OpenAPI spec as a PDF.
- **RapiDoc CLI**: the `rapidoc` command, a page per command.
- **Integrations**: front-end frameworks, server frameworks and documentation sites, and how to build your own.
- **Developer Portal**: the [RapiDoc Portal docs](https://portal.rapidocui.com/), on their own site.

Every attribute, method, event and slot of each element is listed in the [API reference](/api), and the [Examples](/examples) show them running.

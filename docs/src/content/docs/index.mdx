**RapiDoc** turns an OpenAPI spec into interactive API documentation. At its core is `<rapi-doc>`, a single HTML element with no runtime dependencies: add one script tag and it works in any page or framework. Its Shadow DOM keeps your site's styles and RapiDoc's styles apart.

## What you can build

<CardGrid>
  <Card title="API reference" icon="open-book">
    `<rapi-doc>` renders navigation, search, schemas, examples, authentication and a **Try** console. Choose one long page, expandable sections, or one operation at a time. [Quickstart](/docs/get-started/quickstart/)
  </Card>
  <Card title="Your look" icon="pencil">
    Five built-in themes, any brand color, light and dark, and full control through CSS custom properties and `::part()`. [Theming](/docs/theming/overview/)
  </Card>
  <Card title="Embedded endpoints and workflows" icon="puzzle">
    `<rapi-doc-mini>` puts a single endpoint in a blog post; `<rapi-flow>` draws Arazzo workflows and runs them. [RapiDoc Mini](/docs/components/rapidoc-mini/) · [Workflows](/docs/components/workflows/)
  </Card>
  <Card title="Mocks" icon="random">
    Answer requests from the spec, in the page or as an HTTP server with request validation and token checks. [Mocking](/docs/mocking/overview/)
  </Card>
  <Card title="Tools for AI agents" icon="rocket">
    Turn the spec into a curated MCP server, from a button in `<rapi-doc>`, the command line or Node. [MCP Server](/docs/ai/mcp-server/)
  </Card>
  <Card title="Developer portals" icon="laptop">
    API references next to Markdown guides, with search and optional sign-in, built with the `rapidoc` CLI. [Packages](/docs/get-started/packages/#developer-portals)
  </Card>
</CardGrid>

## How these docs are organized

- **Getting Started**: install RapiDoc, use it in your framework, and load your spec.
- **Theming & Styling**, **Customizing Content**, **Authentication**, **JavaScript API** and **Performance**: everything about configuring `<rapi-doc>`.
- **Components**: `<rapi-doc-mini>` and `<rapi-flow>`.
- **Mocking**, **AI & MCP** and **Tools**: what you can do with your spec beyond rendering it.
- **Migration Guides**: upgrading from earlier versions.

Every attribute, method, event and slot is listed in the [API reference](/api), and the [Examples](/examples) show them running.

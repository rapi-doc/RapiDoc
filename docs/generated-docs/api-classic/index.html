Attributes

General Attributes

Attribute NameDescriptionDefault
spec-url
URL of the OpenAPI specification file (JSON or YAML) to load and render.		(empty)
update-route
Allowed : true | false
When set to "true", automatically updates the browser's URL address hash as the user scrolls through or clicks on different sections.		true
route-prefix
Custom prefix prepended to route hashes to integrate seamlessly with third-party routers (e.g.		#
sort-tags
Allowed : true | false
Sorts tags in alphabetical order. When set to "false", preserves the tag order defined in the OpenAPI specification. 		false
sort-schemas
Allowed : true | false
Sorts component schemas alphabetically. When set to "false", preserves the order defined in the spec. Note: Only has an effect if render-style="focused" and show-components="true". 		false
sort-endpoints-by
Allowed : path | method | summary | none
Sorts endpoints within each tag group by path, HTTP method, or summary. 'none' leaves the sort order unmodified.
ⓘ This is a static initialization attribute. It will not have any effect if modified using JavaScript after the spec is rendered.
Example 		path
heading-text
Custom title text displayed on the top-left corner of the header.		(empty)
goto-path
Target endpoint location to navigate to automatically after the specification finishes loading. Must be provided in the format of {method}-{path} (e.g., to focus on GET /user/login, provide get-/user/login). 		(empty)
fill-request-fields-with-example
Allowed : true | false
Pre-populates interactive request parameter inputs and request body fields using example values defined in the OpenAPI spec.		true
persist-auth
Allowed : true | false
Persists authenticated user credentials (API keys, tokens) in localStorage across browser sessions and page reloads.		false

UI Layout and Placement Attributes

Attribute NameDescriptionDefault
layout
Allowed : row | column
Controls the multi-column orientation of request parameters and response panels on desktop screens (>768px). In 'row' layout, request and response sections sit side-by-side; in 'column' layout, they stack vertically. Applicable when render-style="view". 		row
render-style
Allowed : read | view | focused
Controls the overall documentation presentation layout. Three distinct modes are supported:
  • view: Optimized for interactive exploration with collapsible operations | Example
  • read: Continuous narrative page layout, ideal for reading through API specifications from top to bottom | Example
  • focused: Displays a single endpoint at a time with a dedicated sidebar, ideal for large enterprise schemas | Example
read
response-area-height
Allowed: Any valid CSS height value (e.g. 400px, 50%, 60vh).
Controls the vertical height of the interactive response payload viewer. 		300px

Events

Below is an example on how to handle events using plain JS
 
          
            
            <html>
              ...
                <rapi-doc id="the-doc" spec-url = "https://.../spec.yaml"> </rapi-doc>

                <script>
                  window.addEventListener('DOMContentLoaded', (event) => {
                    /*
                      Ensure that the DOM is loaded, then add the event listener.
                      here we are listenig to 'before-try' event which fires when the user clicks
                      on TRY, it then modifies the POST requests by adding a custom header
                    */
                    const rapidocEl = document.getElementById('the-doc');
                    rapidocEl.addEventListener('before-try', (e) => {
                      if (e.detail.request.method === 'POST') {
                        e.detail.request.headers.append('custom-token', 'AAA.BBB.CCC');
                      }
                    });
                  });
                </script>
              ...
            </html>
Event NameDescription
before-renderDispatched before rendering starts. Provides the parsed OpenAPI specification object via e.detail.spec, allowing programmatic modifications before the UI tree is built.
spec-loadedDispatched after the OpenAPI specification has been fully fetched, parsed, resolved, and rendered into the DOM. Provides the resolved spec object in e.detail.
before-tryDispatched when a user clicks "TRY" before the network request is initiated. Provides a mutable Request-like object via e.detail.request to append headers, rewrite parameters, or modify payloads, along with an AbortController via e.detail.controller to abort requests conditionally.

Example: Append custom authorization headers before sending: 
 rapidocEl.addEventListener('before-try', (e) => {
  if (e.detail.request.method === 'POST') {
    e.detail.request.headers.append('X-Tenant-ID', 'corp-acme-123');
  }
});
Example: Append query parameters to all GET requests: 
 rapidocEl.addEventListener('before-try', (e) => {
  if (e.detail.request.method === 'GET') {
    const url = new URL(e.detail.request.url);
    url.searchParams.append('client_version', '2.4.0');
    e.detail.request.url = url.toString();
  }
});
Example: Abort specific requests conditionally: 
 rapidocEl.addEventListener('before-try', (e) => {
  if (e.detail.request.method === 'DELETE') {
    alert('DELETE operations are disabled in this sandbox environment.');
    e.detail.controller.abort();
  }
});
after-tryDispatched after a try request completes. Provides e.detail.request and e.detail.response. In the event of a network or protocol error, provides request and error objects.
request-abortedDispatched when an in-flight API try request is aborted by the user or programmatically via AbortController.
api-server-changeDispatched when the active target API server is modified in the dropdown.
For further information refer to this Example of Event Handling In RapiDoc

Slots

slots are predefined placeholders inside a RapiDoc component. You can use these slots to place your custom html in certain desired locations inside RapiDoc. Below is an example on how to inject HTML/CSS/JS at various locations in RapiDoc
 
          
            
            <html>
              ...
              <rapi-doc spec-url = "https://petstore.swagger.io/v2/swagger.json">
                <div> <!-- HTML Elements without slot attribute goes into default location-->
                  <h1> My HTML Heading  </h1>
                </div>

                <!-- provide slot attribute to place an element at desired location -->
                <img slot="nav-logo" src="https://via.placeholder.com/100" style="width:50px; height:50px"/>

              </rapi-doc>
              ...
            </html>
Slot NameDescription
(default)Any standard markup placed directly inside the `` tag renders immediately below the header bar and above the specification info overview.
logoCustom HTML or image markup to replace the default brand logo in the top header bar.
headerCustom HTML elements rendered in the top header bar following the spec URL input controls.
footerCustom HTML elements rendered at the bottom of the documentation canvas.
nav-logoCustom image or branding markup placed at the top of the sidebar navigation panel (available in read mode).
overviewCustom HTML rendered inside the overview section at the top of the document. Link directly to this anchor using #overview.
serversCustom HTML rendered inside the server configuration section located under the overview container. Link directly using #servers.
authCustom HTML rendered inside the authentication controls panel under the overview section. Link directly using #auth.
operations-topCustom HTML displayed directly above the operations list. Use this slot to provide global announcements, common headers, or usage instructions applicable across all API calls. Link directly using #operations-top.
tag--{tag-name}Inserts custom HTML content underneath a specific tag grouping identified by tag name.
{method}-{path}Inserts custom HTML into a specific endpoint section. Identified by {method}-{path}, where special characters such as brackets, spaces, and hashes are replaced by hyphens (e.g. get-/pet/-petId-).

Supported vendor extensions

Extension NameDescription
x-code-sample
Provides multi-language code snippets (cURL, Python, JavaScript, Go, etc.) for an endpoint.
x-codeSample
Alternative camelCase syntax for x-code-sample. Provides multi-language code snippets for an endpoint.
x-badges
Annotates endpoints with short, color-coded badges (e.g., "Internal", "Beta", "v2"). Combine with the remove-endpoints-with-badge-label-as attribute to filter out restricted or internal APIs from public documentation.
x-tag-expanded
Controls whether endpoints grouped under a tag start expanded or collapsed (applies in view and focused render styles).
x-fill-example
Allowed : yes | no
Specifies whether a parameter's example value should be automatically populated in the interactive console input. To configure this behavior globally for all parameters, see fill-request-fields-with-example.
x-example-show-value
Allowed : true | false
Specifies whether parameter example values should be visibly rendered on the documentation card.
x-client-id
Pre-fills the OAuth2 client ID in authentication modals.
x-client-secret
Pre-fills the OAuth2 client secret in authentication modals.
x-default-scopes
Pre-fills default OAuth2 permission scopes in authentication modals.
x-receive-token-in
Defines whether OAuth2 access tokens are received via HTTP header or request body (header or request-body).
x-pkce-only
Allowed : true | false
When set to "true", enforces Proof Key for Code Exchange (PKCE) flow and prevents client secrets from being transmitted from the browser.

# AGENTS.md — `sites/rapidoc` (rapidocui.com on RapiDoc Portal)

rapidocui.com, built with RapiDoc Portal from this repository's own `@rapidoc/cli` and `@rapidoc/portal`. It replaced the Starlight site that was in `docs/` as the live site on 2026-11-22; that site has since been removed from the repository (its history is in git). Old addresses that moved have no redirects (decided): the `/api/…` pages are the only ones kept for old links.

- **Not an npm workspace**, and nothing here is published to npm.
- **Element references** are docs pages (`docs/rapidoc/reference/`: one page each for attributes, methods, events, slots, spec extensions and CSS parts and variables; `docs/rapidoc-mini/reference.mdx`, `docs/rapipdf/reference.mdx`; RapiFlow's is on its site), each section drawn from the element's source by `sites/shared/components/ElementReference.astro` with the data of `sites/shared/element-api.ts` (`page-data/rapidoc-api.ts` re-exports it). A section's heading is written in the page, so "On this page" lists it. The `/docs` page's product cards link each product's API Reference, these and the other sites'. A reference page sets `tableOfContents: false`: its tables take that column's width, and the component's jump links replace it.
- **RapiFlow's docs** are on their own site, `sites/rapi-flow` (flow.rapidocui.com): the RapiFlow sidebar tab links there, and links to its pages are absolute. Its feature page (`pages/rapi-flow.astro`), API reference and examples stay here.
- **Published by**: `.github/workflows/deploy-docs.yml`, on pushes to `master` that touch this folder, `sites/shared/` or the packages the site is built from: it runs `npm run build:rapidoc-site` and deploys `dist/` with GitHub Pages, whose custom domain (rapidocui.com) is set in the repository's Pages settings, so `public/` has no `CNAME`. The preview at `preview.rapidocui.com` (repository `rapi-doc/rapidoc-site-preview`) is no longer published; it keeps its last build, with `noindex`.
- **Started as a copy** of the Starlight site that was in `docs/` (removed): its docs pages, and its pages and what they import (`layouts/`, `components/`, `utils/`, `page-data/`, `styles/`). Changes are made here. `npm run build-info` (run last by the package builds) refreshes `page-data/rapidoc-build-info.*`; the unit tests import `utils/pageTitle.ts`, `utils/pageMeta.ts`, `page-data/products.ts` and `components/controller-registry.ts`, and the unit, mock and perf tests read `public/specs/` and `specs-test/`, so keep those paths.
- **Docs pages** differ from the originals only in their imports: components come from `@rapidoc/portal/components`, never `@astrojs/starlight/components`, and the site's own from `components/`. `docs/index.mdx` is the page at `/docs` (the home page is `pages/index.astro`), where the header's Docs link goes from every site: a Get started card, then cards for every product, tool and integration (`components/DocsCard.astro`), with "Which package do I need?" below them. A new product gets a card there. Each product's docs are under its own folder: RapiDoc's under `docs/rapidoc/`, then `rapidoc-mini/`, `rapipdf/`, `cli/`, `mcp/`, `prerender/` and `integrations/`. The sidebar is `navigation` in the config: one tab per product or tool; RapiFlow, RapiMock and RapiDoc Portal have their docs on their own sites, so their tabs link there.
- **The docs shell** is the portal's, made to look like the live site: its structure is config (`header.links` with the Products menu as `groups`, `header.tabs: sidebar-select` for the current product above the pages, opening the list of products, `site.logo.badge` for the version, `footer`: the columns every RapiDoc site shares), and `styles/portal.css` sizes and colors it, with the portal's color tokens so the light theme works too. Where the portal and the live site differ in page furniture, the portal's own is kept (decided): its previous/next links, "On this page" list, page actions (Copy page), callouts without a default title, and the light/dark switcher (`theme.mode: dark` is only the first visit's theme). There is one header and one footer, the portal's, on every page: the site's own pages place it themselves (`PortalHeader` from `@rapidoc/portal/components/PortalHeader.astro`, in place of the live site's `SiteNavbar`, and `components/SiteFooter.astro`, which is `@rapidoc/portal/components/PortalFooter.astro`), and `layouts/GlobalLayout.astro` marks them with `data-site-page`, for which `portal.css` gives the header their darker surface and hides the theme switcher (they are dark only). The Products menu and the Docs link are `header.links` in the config; Docs is a plain link to `/docs` on all four sites, whose cards (`components/DocsCard.astro`: icon, name, tag, one line, and shortcuts such as Quickstart and API Reference) replace the Docs menu; the Products menu has Products, Tools and Integrations; `page-data/products.ts` holds the same groups for the home page's product list and the examples' filter, so a new product goes in both. Every product's feature page is here, RapiMock's and RapiDoc Portal's included; their docs are on their own sites. The version in `site.logo.badge` is kept at RapiDoc's version by `scripts/sync-version.mjs`, which the two npm commands below run first; it rewrites that line when the version changes, so commit the config with a release.
- **No Astro config**: the portal owns it. There are no Vite aliases or plugins, so files here differ from the Starlight originals in these ways: `ThemeDemo` imports RapiDoc's theme tokens by relative path (no `~` alias); data files and RapiDoc's source are found from `projectDir` (`virtual:rapidoc-portal/project`), not `process.cwd()`; `components/Icon.astro` finds Phosphor's icons itself; and pages load `/assets/rapidoc-min.js`, the bundle the portal publishes.

## Commands (from the repository root)

| Command | Purpose |
| :--- | :--- |
| `npm run dev:rapidoc-site` | Preview on `http://localhost:4329` |
| `npm run build:rapidoc-site` | Build to `sites/rapidoc/dist/` (ignored by git); builds the `rapidoc`, MCP, prerender and `rapipdf` packages first, which the pages load |

## Layout

```text
rapidoc.config.yaml   # site, header and the sidebar of each product
docs/                 # the documentation pages (MDX)
pages/                # the site's own pages: index (home: the family), a feature page per product (rapidoc, rapidoc-mini, rapi-flow, rapipdf, rapi-mock, portal) and cli, integrations, sandbox, api/[...element] (old addresses: pages that send readers to the references), examples/, tests/
layouts/ components/ utils/ page-data/ styles/   # what the pages import; styles/portal.css is the docs shell's look
public/               # favicon, images, Prism, specs/ and specs-test/ (the specs the examples and tests load)
```

# AGENTS.md — `packages/rapidoc-server` (`@rapidoc/server`)

## 1. Package Scope & Identity

`packages/rapidoc-server` serves a portal built by `@rapidoc/portal` and enforces sign-in and access rules. `rapidoc serve` (in `@rapidoc/cli`) runs it.

- **Package Name**: `@rapidoc/server`
- **Module Type**: ESM (`"type": "module"`)
- **Entry Point**: `src/index.js` (`createApp`, `startServer`, `SettingsError`). Both functions return `summary` (`summaryOf` in `src/index.js`, typedef `ServerSummary`): mode, paths, public URL, issuer, client ID, `providerReady`, `access` counts and `mcp`. That summary is the public shape; the settings object (`loadSettings` in `src/settings.js`) holds the secrets and the manifest and is never returned or exported. A new field for the CLI's start-up lines goes into the summary, never the settings.
- **Dependencies**: `hono` + `@hono/node-server` (HTTP), `openid-client` (OpenID Connect), `jose` (encrypted cookies), `@modelcontextprotocol/sdk` (the `/mcp` transport) and `@rapidoc/mcp` (the runtime that calls the APIs). Dev: `oidc-provider` (a real OIDC provider for tests).

---

## 2. Boundaries

- **No dependency on `@rapidoc/portal` or Astro.** The server reads only the build: `dist/public/`, `dist/protected/`, `dist/rapidoc-server.json` and the MCP manifests in `dist/mcp/`. The build-side contract is `packages/rapidoc-portal/src/access/split-output.js` (and `src/engine/mcp-output.js` for the `mcp` section); change both sides together and keep the manifest `version` in step.
- **MCP comes from `@rapidoc/mcp`** (manifest runtime, no Lit); the server does not depend on `rapidoc`. The server never parses a spec itself; the build already turned the specs into manifests.
- **The server never evaluates rule patterns.** The build gives every file a zone; the server only maps a file to its zone and a zone's allow to the session.
- **Stateless.** No database, no in-memory sessions: the session and the sign-in transaction are encrypted cookies (`src/auth/session.js`). Anything shared between instances must fit that model.
- **Secrets only from environment variables** (`src/settings.js`). Never read them from, or write them to, the build.
- **The CLI loads this package lazily** (an optional peer); never import it at the top of the CLI.

## 3. Security rules

- Default deny: a protected file without a zone in the manifest is never served; an unknown zone allows nobody.
- Signed-out readers can't tell a missing page from a protected one when the default zone isn't public; `/_rapidoc/access/check` gives the same answer (a path with no file is locked for a reader who may not see the default zone). A reader who may see the default zone gets the build's `404.html` (status 404, no-store) when a browser asks for a page that isn't there (`notFound` in `src/index.js`: an `Accept` with `text/html` and a path without a file extension); anything else, and a build without that page, gets the plain `Not found`.
- Responses that depend on the session: `Cache-Control: private, no-store` and `Vary: Cookie`.
- `returnTo` stays on this site (`safeReturnTo`); sign-out is same-origin only (`isSameOrigin`).
- The ID and refresh tokens never reach the browser or a cookie. The access token does only with `auth.tryIt`: in its own encrypted cookie (`rapidoc-api-token`), and to the page only through `GET /_rapidoc/auth/token` (same-origin, no-store). Only groups named by some rule go into the session.
- Every sealed token has one use (`SEAL_USES` in `auth/session.js`: `session`, `sign-in`, `api-token`, `mcp`), each with its own key from `RAPIDOC_SESSION_SECRET`; `seal()` and `open()` take the use, and a token opens only as what it was sealed for. A session must also name its user (`sub`): the sign-in cookie, which `/login` gives anyone, is never a session. Never seal or open without a use.
- **The provider at start-up**: `createApp` discovers it once. A wrong issuer (a 4xx answer, another issuer's document, no discovery document: `isUnreachable(err)` false in `auth/oidc.js`) is a `SettingsError`. A provider that is down (network error, timeout, 5xx) is logged and the app is built anyway: public pages are served, protected ones still redirect to sign-in, and `createProviderSource` discovers again when a reader reaches `login` or `callback` (one try at a time, then a back-off of 5 seconds doubling to a minute). Until then both routes answer with the sign-in error page (`?reason=provider`), and `logout` with `logout: idp` signs out of the portal only (it uses `providerSource.current()` and never waits for the provider). A route that needs the provider takes it from `providerSource`, never from a variable captured at start.
- **Log lines** carry the reader's `sub`, never the email or name. A value that comes from the request (the provider's `error` parameter) goes through `logValue` (`auth/routes.js`): control characters removed, cut to 200 characters.
- A build folder with `protected/` and no `rapidoc-server.json` is refused at startup, never served as static files. With `auth` and no public URL (`site.url`, `RAPIDOC_PUBLIC_URL`), only requests to a loopback host are answered: the origin, the cookies' `Secure` flag and the redirect URI are never taken from another host's request. POST bodies are limited while they are read (`tooLarge` in `static.js`). Every response has `nosniff`, a referrer policy, HSTS when the public URL is https, and `frame-ancestors` (`RAPIDOC_FRAME_ANCESTORS`; `'self'` by default with `auth`).
- MCP tokens (`POST /_rapidoc/mcp/token`, same-origin, signed in) are sealed for the `mcp` use and marked `mcp: true`, so a session cookie is never accepted as a bearer token and an MCP token never as a cookie. `/mcp` answers a bad token with 401, lists only the tools of zones the reader may see, and calls the API with the embedded access token for bearer-style schemes only. `RAPIDOC_MCP=off` registers neither `/mcp` nor the token route, and `/_rapidoc/auth/me` says `mcp: false` so the user menu hides its agent section; any value other than `on`/`off` is a settings error.

## 4. Files

| File                  | Role                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| :-------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `src/index.js`        | `createApp()`: routes and the per-request decision; `startServer()`. `mount()` takes the mount path off each request, so routes see paths relative to the portal; URLs sent back (redirects, OIDC callback, `returnTo`) get `settings.basePath` (the path of `site.url`, from the manifest)                                                                                                                                                                                                                   |
| `src/settings.js`     | Manifest + environment variables → settings; fails fast with every problem listed                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `src/access.js`       | `allows`, `decide`, `visibleZones`, email patterns                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `src/static.js`       | URL path → file (no traversal), streamed responses, cache headers                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `src/search.js`       | Merged `search-index.json`; per-zone Pagefind bundles with the empty-bundle fallback                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `src/auth/oidc.js`    | Discovery (`discoverProvider`, `isUnreachable`, `createProviderSource` for a provider that was down at start), PKCE sign-in, code exchange + userinfo, end-session URL, claim paths                                                                                                                                                                                                                                                                                                                           |
| `src/auth/session.js` | Encrypted cookies (JWE dir + A256GCM), cookie names (`__Host-` on https)                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `src/auth/routes.js`  | `/_rapidoc/auth/{login,callback,logout,me,token}`                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `src/mcp.js`          | `POST /mcp` (one SDK `Server` + stateless Streamable HTTP transport per request, tools filtered by `visibleZones`, calls through `@rapidoc/mcp`) and `POST /_rapidoc/mcp/token`; `loadMcpManifests()` reads `dist/mcp/`, leaving out (with a log line) a manifest of another `manifestVersion` and the tools of an API with no base URL. From the environment it reads only `MCP_AUTH_<SCHEME>`, `MCP_BASE_URL[_<API ID>]` and `MCP_EXTERNAL_HOSTS`, through `@rapidoc/mcp`: never a variable named by a spec |

## 5. Tests

`npm test` (or `npm run test:portal` from the monorepo root). `tests/helpers.js` starts `oidc-provider` on a random localhost port, writes a fixture build, and drives the app with a cookie-keeping client that calls `app.fetch()` for the portal origin (`http://portal.test`). Add a case to `tests/server.test.js` for every change to the decision table or the auth routes.

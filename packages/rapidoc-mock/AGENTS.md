# AGENTS.md — `packages/rapidoc-mock` (`@rapidoc/mock`)

## 1. Package Scope & Identity

`packages/rapidoc-mock` is a mock server for the APIs of a portal: examples first, then generated data, request validation, and each operation's `security` enforced with real token checks. `rapidoc mock` (in `@rapidoc/cli`) runs it.

- **Package Name**: `@rapidoc/mock`
- **Module Type**: ESM (`"type": "module"`)
- **Entry Point**: `src/index.js` (`createMockApp`, `startMockServer`, `tokenScopes`, `DEFAULT_PORT`)
- **Build**: only the Mock UI (`npm run build`, or `npm run build:mock` at the root; `pretest` and `pretest:portal` run it). `src/` is published as source.
- **Dependencies**: `hono` + `@hono/node-server` (HTTP), `jose` (JWT/JWKS), `openapi-backend` (routing, request validation), `json-schema-faker` (data), `@faker-js/faker` (named values and word lists for seed data), `@apidevtools/json-schema-ref-parser` (bundling), `ajv` + `ajv-formats` (checking generated data).

---

## 2. Boundaries

- **No dependency on `@rapidoc/portal` or Astro.** The CLI reads `apis:` with `loadConfig` and passes `{ id, fullPath, title }`; this package only reads spec files.
- **Libraries stay behind the adapters in `src/engine/`.** `router.js` is the only file importing openapi-backend (`match`, `validate`); `faker.js` the only one importing json-schema-faker (`fake(schema, seed)`). `values.js` is the only one importing @faker-js/faker (`valuesFor(seed)`, `WORDS`). Swap a library there and keep the interface; everything else works on the bundled OpenAPI document.
- **No `rapidoc.config.yaml` keys.** Settings are CLI options and `RAPIDOC_MOCK_*` variables. Adding a config key (e.g. `mock:`) is a config contract change: ask first.
- **`mock.config.yaml` is the stateful mode's own file** (the user's corrections: `resources.<Name>.key`, `operations.<id>` with `resource`, `action`, `key`; under `apis.<id>` for several APIs; `version: 1`, optional, names the format: bump `CONFIG_VERSION` only for a change that would misread an older file). Its keys are a contract too: ask before adding one. This package takes it parsed (`stateful.config`); the CLI finds and reads the file, so the mock needs no YAML parser of its own.
- **The CLI loads this package lazily** (an optional peer); never import it at the top of the CLI.

---

## 3. Auth rules (`src/auth.js`)

- Requirements are alternatives; schemes inside one requirement are all needed. `security: []` is open.
- Token schemes (oauth2, openIdConnect, http bearer) need a JWT verified against the issuer's JWKS (discovered at start; a wrong issuer fails the start), with `issuer` and, when set, `audience` checked. Scopes come from `scope`, `scp` and `permissions`.
- A bearer requirement without scopes takes the operation's OAuth scopes (the demo convention: the oauth2 scope is the permission, whichever scheme carries the token).
- `401` (missing or invalid token, `WWW-Authenticate: Bearer`, `error="invalid_token"` when one was sent) unless some alternative failed only on scopes: then `403` with `error="insufficient_scope"` and the missing scopes.
- Auth runs before request validation: a caller without access learns nothing about the request format.
- Without an issuer, bearer tokens are accepted unchecked; say so wherever the mock starts.

## 5. Tests

`npm test` (or `npm run test:portal` from the monorepo root). `tests/fixtures/core-specs/` holds 14 real specs the stateful mode is checked against (the first twelve are what it was written against; Jira and DigitalOcean were added for the patterns those lack) (its README has their sources and licenses; they are test data and must stay unpublished); `tests/core-specs.test.js` keeps a baseline of what the classifier and the seed generator produce for each. The baseline has the label counts, how completely each spec's records are mapped (`COMPLETENESS`: label counts hid half-working resources), the invalid seed records, and the specs whose seed fails (`SEED_FAILS`). To learn how the mock does on unseen specs, measure on specs outside that folder and don't tune against them. `tests/helpers.js` starts a token issuer (discovery + JWKS from a jose key pair) on a random localhost port and signs tokens; `tests/fixtures/` holds a 3.1 spec with a relative `$ref` file and a 3.0 spec. Add a case for every change to the auth rules or response selection. `tests/stateful.test.js` runs the stateful server against three of the core specs; `tests/control.test.js` covers `/__mock`. The CLI side (`rapidoc mock`) is tested in `packages/rapidoc-cli/tests/cli.test.js`.

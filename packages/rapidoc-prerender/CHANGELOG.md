# @rapidoc/prerender

## 1.0.0

### Major Changes

- aa3c878: RapiDoc and its family, in sync: RapiDoc Portal and the RapiDoc CLI (with the server, the mock, the prerenderer, the MCP builder and `create-rapidoc`), the integration contract (`@rapidoc/embed`) and RapiDoc for Hono, Express and Fastify were reviewed end to end together with `rapidoc` 15 and are 1.0.0, a new start for the family. The same names for the same things, one sidebar from `<rapi-doc>` to the portal, and safer defaults everywhere; names that were wrong or unclear were corrected once, with no old spellings kept: the portal site's "Upgrading from 0.2 to 1.0" page lists every change. From here they follow semver: a breaking change to the config, the CLI, the integration contract or an integration's options comes only in a new major version.

### Patch Changes

- aa3c878: `rapidoc/flow` (`<rapi-flow>`) is 41 KB smaller (283 KB to 242 KB minified, 89 KB to 76 KB gzipped): Arazzo documents are now read with `js-yaml`, half the size of `yaml`. Values are read the same way (YAML 1.2, merge keys, no dates); a tag the reader does not know keeps its plain value, and stray control characters are dropped. `@rapidoc/mcp` depends on `js-yaml` in place of `yaml`, and `@rapidoc/prerender` on both. OpenAPI specs are read as before. In `rapidoc-min.js`, the syntax highlighter no longer carries grammars for Astro, Svelte, Vue, Objective-C, Perl, R and TOML. The first three are drawn as HTML and Objective-C as C; Perl, R and TOML code shows as plain text.
- f0c81ab: The navigation bar's filter area has its frosted-glass background again in Chrome and Edge: the minified bundle had kept only the `-webkit-` prefixed `backdrop-filter`. In the navigation bar, colored method badges have 2px corners and operation names are 1px smaller. The `amber` theme's light scheme has a deeper copper accent, `#ab6534`, with white text on it (was `#ff791a` with black text).
- aa3c878: Clean-up of `@rapidoc/prerender` before 1.0.0. Options have one name each, the name of `<rapi-doc>`'s property: `usePathInNav` is now `usePathInNavBar`, `renderSchema`'s `style` is `schemaStyle`, the API key option is `apiKeyName`, and `getNavFilterHtml` takes `searchPlaceholder` only. Every option that is an attribute of `<rapi-doc>` can also be written in kebab-case, in every function, and an option name a function does not know is an error that lists the valid ones (`renderRapiDoc` still passes any other attribute on to the element). `renderRapiDoc` writes an attribute only for an option you passed and renders with the element's own defaults, so the defaults are now `layout: "row"`, `schemaStyle: "tree"` and `allowAdvancedSearch: true`; pass the old values (`"column"`, `"table"`, `false`) to keep them. A spec that cannot be loaded throws an error that says what was being loaded and why, in place of an almost empty result, and a path that is not a file is `file not found`, not a request to `http://localhost`. `getSpecNavigation` returns exactly the documented fields of an operation. A closing slash on `basePath` no longer gives two forms of link. Removed from the exports: the default export, `resolveSpecInput`, `renderNavBarHtml`, `renderTemplateToString`, `escapeHtml` and `getMethodBadge` (use `getNavBarHtml`; the others are internal), the types `RapiDocOptions` and `RenderNavBarHtmlOptions` (now `RenderRapiDocOptions` and `NavBarOptions`), and the `theme` and `colorScheme` options of `getBundledCss`, which did nothing. In RapiDoc Portal, a build now fails, naming the API and the spec, when a spec cannot be read, parsed or fetched, where it used to publish the API page with an empty sidebar; `rapidoc dev` shows the error on that API's page. An API whose `spec` is a URL gets its tag pages (the sidebar's links to them returned 404), from one fetch at build time. Search results for operations open the operation: they link to its tag's page and anchor as the sidebar does, and operations marked `x-internal` or `x-hidden` are not in the index. The "RapiDoc bundle is missing" error tells npm users to reinstall `rapidoc`.
- aa3c878: `<rapi-doc>` 15 clean-up. Removed: the `scrollTo(elementId)` method (use `scrollToPath`; `scrollTo` is the browser's own method again), `mock-server-status-strategy` (write the strategy in front of the codes: `mock-server-status-code="random:200, 500"`), `theme="light"` and `theme="dark"` (use `color-scheme`), `default-schema-tab="model"` (use `schema`), `mcp="none"` (use `false`), the hidden "Operations" sidebar row with its part `section-navbar-operations-top`, and `loading`, `focusedElementId`, `searchVal` and `advancedSearchMatches` as attributes. `nav-active-change` has one detail from every source, `{ elementId, type, operationId? }`: `id` is gone, `type` is `operation`, `tag` or `section`, and `operationId` is the spec's own operationId. `persist-auth` saves keys per API (by spec URL, else title), so two APIs on one site no longer share a token; keys saved by v14 are not carried over, and saved keys are applied once per spec load, so a key set with `setApiKey` on `spec-loaded` stays. Relative server URLs (`api/v1`, `../v2`, `/v1`) resolve against the spec's address. Fixed: the mock stays on after the element is moved in the page; OAuth with a scheme name that has a dot or starts with a digit; the Authentication section with a server URL such as `//host` or `{scheme}://host`; `css-file` copied once instead of on every render; the header's local file button reads YAML and reports a file it cannot read. The sidebar follows right-to-left pages, strikes deprecated operations through, and applies `nav-item-overflow` to description headings. The API reference, types and schema no longer list removed attributes; the docs have a "Removed attributes" page instead. `@rapidoc/starlight` and `@rapidoc/docusaurus` read `detail.elementId` only.

  The sidebar is usable with a keyboard and a screen reader: every item is a real link (so it is announced as one, opens in a new tab with a middle click, and shows its address), a tag's arrow is a separate button that answers Enter and Space, the current item is marked with `aria-current`, and the menu button of narrow layouts says whether the menu is open and Escape closes it. The look, class names and CSS parts are unchanged.

- aa3c878: Security fixes. `@rapidoc/server`: the sign-in cookie, which `/_rapidoc/auth/login` gives any visitor, was accepted as a session, opening pages for all signed-in readers without signing in (pages limited to groups or emails were not affected); every sealed cookie and token now has one use. The server also refuses a build whose `protected/` folder has no `rapidoc-server.json`, needs a public URL (`site.url` or `RAPIDOC_PUBLIC_URL`) to sign readers in anywhere but `localhost`, limits request bodies, and sends `frame-ancestors` (`RAPIDOC_FRAME_ANCESTORS`), referrer and HSTS headers. `rapidoc` and `@rapidoc/prerender`: HTML in descriptions is reduced to a fixed list of elements and attributes, in every browser and in pre-rendered pages, where it was not sanitized at all; `javascript:` addresses from a spec are no longer links; a spec value can no longer pass for a template in the prerenderer. `rapidoc build` refuses an output folder that is, holds or is inside a source folder (`--out-dir public` emptied `public/`). `rapidoc mock` and `rapidoc dev` listen on `localhost` by default (`--host 0.0.0.0` for a container or a shared server; `dev` has `--host` now), and the mock takes an imported spec only from a program on its machine or its own page, never from another site's page or through a proxy, and does not let it read other local files.
- aa3c878: The sidebar has a new look with three levels: upper-case section labels (Overview, tag groups, Components, or the tags themselves when there are no tag groups), rows with icons for the API title, servers and authentication, and compact operation rows under a guide line with the method first. The current item is a filled block. A tag's name opens a closed tag as well as going to its section. `nav-item-spacing` is removed (set `--sidebar-item-padding` instead), tag groups no longer collapse, and `show-method-in-nav-bar` now defaults to `as-colored-text`. See the v14 to v15 migration guide. RapiDoc Portal's docs sidebar takes the same three levels: a tab's top-level groups are section labels, their items rows with icons, deeper items compact rows under a guide line.

- cc15663: Faster rendering of large specs: a schema's nested fields are built and rendered only when they are shown, so with `schema-expand-level` a collapsed field costs nothing until it is opened, and a response status's example and schema render only once that status is selected. The Stripe spec in read mode with `schema-expand-level="1"` now renders in under 5 seconds instead of over 20. Very large schemas are cut below depth 4 as they grow past the node budget, instead of being rebuilt shallower.
- 90d213f: The mock's badge in the API Server section reads MOCKING, with a pulsing light blue dot beside it (still when the reader prefers reduced motion); the "(Mocked)" note after the selected server is gone.
- a84c379: `mock-server-status-code` takes the strategy in front of the codes (`random:200, 500`, `cycle:503, 503, 200`), also per operation in its JSON map, and a list without a prefix is now used in turn (`cycle`) instead of always answering its first code; each operation's cycle starts again when the codes change. `mock-server-status-strategy` (now defaulting to `cycle`) and its `first` value are deprecated. In RapiFlow, an Arazzo step's `x-mock-server-status-code` prefills its Mock Response Status field, each field takes the same prefix, and the separate "in turn / at random" select is gone.
- 5f050fe: Sidebar items whose operation shows a badge (`x-badges`, or an OpenAPI 3.2 tag of `kind: badge`) get a small dot in the first badge's color, with the badges in its tooltip and accessible label: `show-badges-in-nav-bar`, `dot` by default, `false` to turn it off (CSS part `nav-badge-dot`). - 90d213f: OpenAPI 3.2: streamed bodies (`itemSchema` on Server-Sent Events, JSON Lines and JSON Text Sequences) show the schema of one item and the example as a stream, and Try shows a streamed response as it arrives, with a STOP button. Also shown: a response's `summary`, a server's `name`, deprecated security schemes, and XML `nodeType: element` wrapping arrays.
- 90d213f: OpenAPI 3.2 tags: a tag's `summary` is its name in the navigation, tags with a `parent` are grouped under it (as with `x-tagGroups`), tags of a `kind` other than `nav` no longer become sections (`badge` tags show as badges), and Example Objects' `dataValue` is shown as the example.
- 90d213f: Operation badges (`x-badges` and OpenAPI 3.2 `kind: badge` tags) use the shared badge style (2px radius, 4px padding, weight 500) in the badge's colour, with the same 15% tint in every render style; the base badge's padding, radius and weight change accordingly, and the unused `.badge-sm` and `.btn-destructive` styles are gone.

- 90d213f: RapiFlow's action labels on lines and its END pills are outlined instead of filled (a border in the action's colour, the surface behind them, text mixing the colour with the foreground), so they read at 4.5:1 or more on every theme in both colour schemes; a step's default END keeps a dashed border.

CSS parts: `btn-stop` (was `btn-stop-stream`), `response-status-line`, `response-spinner`.
- 90d213f: XML examples name array items by the items' `xml.name` (else the property's name) instead of their index (`<0>`), also when the array or its items have an example; unwrapped arrays put the items directly in the parent element.

## 0.2.0

### Minor Changes

- 5066e13: `<rapi-doc>` and `<rapi-doc-mini>` choose which operations to show with one attribute, `filter-operations`, replacing `match-paths`, `match-type` and `remove-endpoints-with-badge-label-as` (removed).

Clean-up of `@rapidoc/prerender` before 1.0.0. Options have one name each, the name of `<rapi-doc>`'s property: `usePathInNav` is now `usePathInNavBar`, `renderSchema`'s `style` is `schemaStyle`, the API key option is `apiKeyName`, and `getNavFilterHtml` takes `searchPlaceholder` only. Every option that is an attribute of `<rapi-doc>` can also be written in kebab-case, in every function, and an option name a function does not know is an error that lists the valid ones (`renderRapiDoc` still passes any other attribute on to the element). `renderRapiDoc` writes an attribute only for an option you passed and renders with the element's own defaults, so the defaults are now `layout: "row"`, `schemaStyle: "tree"` and `allowAdvancedSearch: true`; pass the old values (`"column"`, `"table"`, `false`) to keep them. A spec that cannot be loaded throws an error that says what was being loaded and why, in place of an almost empty result, and a path that is not a file is `file not found`, not a request to `http://localhost`. `getSpecNavigation` returns exactly the documented fields of an operation. A closing slash on `basePath` no longer gives two forms of link. Removed from the exports: the default export, `resolveSpecInput`, `renderNavBarHtml`, `renderTemplateToString`, `escapeHtml` and `getMethodBadge` (use `getNavBarHtml`; the others are internal), the types `RapiDocOptions` and `RenderNavBarHtmlOptions` (now `RenderRapiDocOptions` and `NavBarOptions`), and the `theme` and `colorScheme` options of `getBundledCss`, which did nothing. In RapiDoc Portal, a build now fails, naming the API and the spec, when a spec cannot be read, parsed or fetched, where it used to publish the API page with an empty sidebar; `rapidoc dev` shows the error on that API's page. An API whose `spec` is a URL gets its tag pages (the sidebar's links to them returned 404), from one fetch at build time. Search results for operations open the operation: they link to its tag's page and anchor as the sidebar does, and operations marked `x-internal` or `x-hidden` are not in the index. The "RapiDoc bundle is missing" error tells npm users to reinstall `rapidoc`.

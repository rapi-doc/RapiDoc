Clean-up before 1.0.0 of the integration contract and RapiDoc for Hono, Express and Fastify. `uiPath` now means the same everywhere: the path within the app, router or plugin the integration is registered in. RapiDoc for Hono follows it, so under `basePath("/v1")`, `app.route("/v1", sub)` or `app.use("/v1/*", ...)` the page is at `/v1/docs` with correct links, and a `uiPath` that held the full path must drop the prefix. The 0.x names are removed: the options `path` (use `uiPath`) and `publicPath` (use `publicUiPath`), and the export `DEFAULT_PATH` (use `DEFAULT_UI_PATH`); a request to `createResponder` takes `mount`, the prefix the framework took off the path, in place of a per-request `publicUiPath`. An option that is an empty string counts as not set (`lang: ""` is `en`, `assets: ""` is `bundled`; the site root is `uiPath: "/"`). The bundle is served with `cache-control: no-cache` and its ETag in place of `max-age=3600`, so browsers load a new RapiDoc build on the first visit after a deploy and get a 304 otherwise; `If-None-Match` may be a list or a weak validator, and every response has `x-content-type-options: nosniff`. RapiDoc for Express and Fastify build correct links for a `uiPath` without a leading slash under a mount point or prefix, and RapiDoc for Fastify also answers at `{uiPath}/`. Peer ranges have upper bounds: `hono ^4`, `express ^4 || ^5`, `fastify ^4 || ^5`. `@rapidoc/embed/sidebar` has its own types. The contract (still version 2) now compares a page's inline spec as parsed JSON and the rest byte for byte, and has six more fixtures.

Clean-up of the server's and the mock's JavaScript API and a few behaviours before 1.0. `createApp()` and `startServer()` of `@rapidoc/server` return a `summary` (mode, paths, public URL, issuer, client ID, `providerReady`, counts of protected files and zones, MCP tools) in place of the internal `settings` object and the separate `mcp` value, so no secret can be read from what they return; `loadSettings` is no longer exported. `rapidoc serve` now starts when the sign-in provider is down: public pages are served, sign-in ends on the sign-in error page, and the server finds the provider again when a reader signs in; a wrong issuer still stops the start. `/_rapidoc/access/check` no longer tells a signed-out reader which paths exist, and the server's log has the reader's id only, not the email. `@rapidoc/mock` exports only `createMockApp`, `startMockServer` and `DEFAULT_PORT`; neither function returns the token `verifier` any more, and the helpers `rapidoc lint` uses (`exampleError`, `configFor`, `statefulFindings`, `statefulReport`) moved to `@rapidoc/mock/internal`, which is not public API (`tokenScopes`, `CONTROL_PREFIX`, `CONFIG_FILE`, `STATEFUL_RULES`, `ImportError` and `isLocalCaller` are gone from the entry). In the mock, a `security` requirement that names a scheme the spec does not define now answers 401 (it was left open) with a warning at start, each API keeps at most 1000 `X-Mock-Session` sessions (the one used longest ago is dropped first), and a malformed percent-escape in a `/__mock` path answers 400, not 500.
